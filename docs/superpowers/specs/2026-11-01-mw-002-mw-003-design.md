# MW-002 and MW-003 design

Issues [#2](https://github.com/javakishore-veleti/NorthStar-AI-Harness-eCommerce-Analytics/issues/2) and [#3](https://github.com/javakishore-veleti/NorthStar-AI-Harness-eCommerce-Analytics/issues/3). MW-001 is already on `develop`.

## MW-002

`north_start_ecomm_mcp.common.singleton.Singleton` is the metaclass for later facade implementations, DAO implementations, and the database gateway. Two constructions of one class return the same instance. Subclasses do not share that instance.

`tests/closed_layer_audit.py` scans `domains/` when that tree exists. An empty or missing `domains/` tree passes. The audit rejects presentation imports of `daos`, `tasks`, or `common.database`; facade-implementation imports of `daos`, `common.database`, or another domain's facade; task imports of a facade or `common.database`; and DAO imports of a facade, a task, or presentation.

`proposal_facade_impl.py` may import the customer facade factory (`customer.facades.objects_factory`). That file still cannot import a DAO. A task cannot use the same factory import.

## MW-003

`DatabaseGateway` uses `Singleton`. The file is `NORTHSTAR_COMPANY_DB`, otherwise `Middleware/north-start-ecomm-mcp/.runtime/company.db`. The first construction creates `customers`, `issues`, `revenue`, and `outbox`, then inserts the DESIGN.md seed with `INSERT OR IGNORE`. `read` opens a read-only connection. `write` opens a separate connection. No domain package imports this module. `.runtime/` stays untracked.
